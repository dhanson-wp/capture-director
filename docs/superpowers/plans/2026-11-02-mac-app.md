# Capture Director for Mac Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native SwiftUI Mac app that shows every capture in the library, organizes them into nested project folders, and drags the real video file out into any upload page or app.

**Architecture:** The app is a Swift package in `mac/`, scaffolded from BAMA's `new-mac-app` template with SwiftData removed. It reads `library.json` directly and watches it for changes. Every write goes through new `capture-director library` subcommands in Node, so the library's rules live in one place. `capture-director install-app` builds, signs ad hoc, and installs `Capture Director.app`.

**Tech Stack:** Swift 6.2+ / SwiftUI / AVFoundation / Quick Look (macOS 26+), Swift Testing, Node 20+ (`node:test`), ffmpeg/ffprobe (already required by the CLI).

**Spec:** `docs/superpowers/specs/2026-10-27-mac-app-design.md`

## Global Constraints

- Work on a branch named `mac-app`. The first commit holds the spec and this plan. Don't commit `.impeccable/config.json`; Derek decides that one separately.
- macOS 26 or later, Swift tools 6.2, `.defaultIsolation(MainActor.self)` on the app target (from BAMA's template).
- Command Line Tools only. Never require Xcode. No `actool`; the icon is built with `iconutil`.
- Swift tests run through `mac/tools/test.sh`, because Command Line Tools need explicit framework paths for Swift Testing (verified on Derek's Mac 2026-11-02):
  `swift test -Xswiftc -F$F -Xlinker -F$F -Xlinker -rpath -Xlinker $F -Xlinker -rpath -Xlinker $L` with `F=/Library/Developer/CommandLineTools/Library/Developer/Frameworks` and `L=/Library/Developer/CommandLineTools/Library/Developer/usr/lib`. The script uses those flags only when `xcode-select -p` points at CommandLineTools.
- No SwiftData. `library.json` (in `$CD_HOME` or `~/.capture-director`) is the only record.
- The app never moves, renames, or deletes video files, and makes no network calls.
- The app never writes `library.json` itself. All writes go through `capture-director library …` subcommands.
- Bundle: executable `CaptureDirector`, display name and app folder `Capture Director.app`, bundle id `io.github.dhanson-wp.capture-director`, installed to `~/Applications` by default.
- Unsorted means a `project` that is empty, missing, or the literal `Unsorted`.
- Folder paths use `/` between levels. Each level is trimmed, empty levels are dropped, and the whole path is at most 300 characters.
- Brand accents: mulberry `#4c1637` (accent color), citron `#e5d935` (Final badge), pool `#d4e9ed` (quiet highlights). System font and SF Symbols.
- User-facing copy (README, help text, UI strings) follows Derek's voice: no em dashes, contractions, sentence case headings.
- Sidebar footer copy, verbatim: "Local only. Your videos stay where they were rendered."
- Drag hint copy, verbatim: "Drag into any upload page"
- Every CLI command still prints a JSON summary on stdout and exits 1 with `[capture-director] <message>` on stderr when it fails.

## Review Focus

1. **The CLI can't run** (Node upgraded, repo moved, `install-app` never run). The app should show one plain message telling you to run `capture-director install-app` again, and keep browsing and dragging working. Pinned in Task 6 (`cliMissingNodeGivesReinstallMessage`).
2. **Old or partial entries** (no `size`, `url`, `duration`, `updated`, or a non-ISO date). They should load with blanks, never drop the whole library. Pinned in Task 2 (`oldEntriesLoadWithBlanks`).
3. **A video file that's gone.** The card shows "File moved," drag and Share are disabled, and Locate… works. Pinned in Task 10 (`missingFilesAreFlagged`) and Task 3 (`relocate rejects a missing or non-video file`).
4. **Odd folder names** (`" a / /b "`, `"Unsorted"`, trailing slashes, emoji). They normalize the same way in Node and Swift. Pinned in Task 3 (`normalizeFolder`) and Task 5 (`folderPathsNormalizeLikeNode`).
5. **Renaming a folder into itself or onto an existing folder.** Refused with a plain message, and nothing changes. Pinned in Task 4 (`renameFolder refuses its own descendant and an existing path`).

### Task 4: Library subcommands in Node

**Files:**
- Modify: `src/library.js`, `bin/capture-director.js`
- Test: `test/library-data.test.js`

**Interfaces:**
- Consumes: `normalizeFolder`, `folderPaths`, `load`, `save` from Task 3.
- Produces (all in `src/library.js`, each loading, changing, and saving once):
  - `addFolder(p) -> { folders }`. Refuses `''` with `Pick a folder name`.
  - `renameFolder(from, to) -> { folders, moved: number }`. Rewrites the prefix on every entry and folder under `from`, sets `renames[from] = to`, and repoints any existing rename whose value was under `from`. Refuses `to` equal to or inside `from` with `Can't move a folder into itself`, and an existing `to` with `There's already a folder called <to>`.
  - `removeFolder(p) -> { folders }`. Refuses with `<p> isn't empty` if any entry is in it or below it. Otherwise it removes it and its descendants from `folders`.
  - `setEntries(ids, { project?, starred?, title?, notes? }) -> entry[]`, through the same rules as `applyEdits`. Throws `No capture with id <id>` for an unknown id before changing anything.
  - `forget(ids) -> { forgotten: string[] }`. Removes the entries and their thumbnails, never the files.
  - `relocate(id, file) -> entry`. Accepts only `.mp4`, `.mov`, and `.m4v` that `probe` reads. It keeps the id, refreshes `file`, `size`, `duration`, `width`, `height`, and `hasAudio`, and clears the thumbnail. Refuses a file another entry already points at with `That video is already in the library`.
- Produces CLI (help text lines too):
  - `capture-director library folder add <path>`
  - `capture-director library folder rename <from> <to>` (`move` is the same command)
  - `capture-director library folder remove <path>`
  - `capture-director library set <id>... [--project <path>] [--star|--unstar] [--title <text>] [--notes <text>]`
  - `capture-director library forget <id>...`
  - `capture-director library relocate <id> <new path>`
